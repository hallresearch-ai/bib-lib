## Proposed cleanup and normalization plan

### 1\. Establish safeguards and conventions

Before changing records:

- Select the canonical source of truth: preferably the XLSX during cleanup, followed by a generated BibTeX export.
- Preserve an untouched snapshot of the current workbook.
- Define a written normalization policy covering names, dates, titles, identifiers, entry types, and missing values.
- Assign every proposed change a status such as `proposed`, `approved`, or `rejected`.
- Maintain a change log keyed by `citation_key`.

### 2\. Resolve duplicates

Review likely duplicates using this evidence order:

1. DOI, PMID, arXiv ID, ISBN, or other unique identifier
2. Normalized title and author overlap
3. Publication venue and year
4. Preprint versus published-version relationship

For each group:

- Merge true duplicates into the strongest record.
- Prefer published versions over preprints where appropriate.
- Retain both when they represent meaningfully different editions or versions.
- Record retired citation keys so documents using them can be updated safely.

### 3\. Normalize external identifiers

Apply consistent representations:

- DOI: store as bare identifiers, such as `10.1109/5.726791`.
- URL: use canonical HTTPS landing pages where available.
- arXiv: store the identifier in `eprint`, with `archiveprefix = arXiv`.
- ISBN: remove unnecessary punctuation while preserving ISBN-10 or ISBN-13 intentionally.
- PMID, PMCID, LCCN, standards numbers, and report numbers: use their dedicated fields.
- Remove tracking parameters and duplicated DOI URLs.
- Avoid generic homepages when a record-level page exists.

### 4\. Normalize entry types and field placement

Map records consistently to types such as:

- `article`
- `inproceedings`
- `incollection`
- `book`
- `techreport`
- `manual`
- `standard`
- `online` or `misc`

Move information into the proper fields—for example, conference names into `booktitle`, journals into `journal`, report organizations into `institution`, and edition information into `edition`.

### 5\. Normalize titles and capitalization

Use sentence case or another chosen house style consistently while preserving required capitalization with BibTeX braces:

- Acronyms: `{AI}`, `{NLP}`, `{H2O}`
- Proper names: `{ChatGPT}`, `{RoBERTa}`, `{Microsoft}`
- Mathematical symbols and technical terms where case matters

Preserve official title wording. Do not silently “correct” version-title differences without checking the cited edition.

### 6\. Normalize people and organizations

For personal authors:

- Use consistent `Family, Given` formatting.
- Preserve initials deliberately.
- Normalize particles, suffixes, accents, and compound surnames.
- Replace accidental variations only after identity confirmation.

For institutional authors:

- Protect the complete organization name with braces so BibTeX does not parse it as a person.
- Adopt one canonical form for recurring organizations such as NIST, H2O.ai, and Microsoft.

### 7\. Normalize dates

Choose a single policy:

- `year` should contain a four-digit year only.
- Put months in `month` and exact dates in `date`.
- Convert Excel date serials to explicit date values before export.
- Distinguish publication dates from access dates.
- Replace placeholders such as `\the\year` with a verified year or leave the field blank under a documented rule.

### 8\. Normalize publication metadata

Standardize:

- Journal and conference names
- Publisher and institution names
- Volume, issue, and page ranges
- Editions and report numbers
- ISSNs and ISBNs
- Conference proceedings metadata

Decide whether journal names should be written in full or abbreviated, then apply that policy consistently.

### 9\. Clean URLs and access metadata

For web resources:

- Prefer durable publisher, repository, government, or archival URLs.
- Use `urldate` consistently when access dates matter.
- Replace dead links only after confirming the replacement represents the same version.
- Consider archived URLs when no live authoritative copy remains.
- Flag mutable pages whose current contents may differ from the cited version.

### 10\. Review citation keys

Do this late, because changing keys can break documents.

- Define a stable key format, such as `FirstAuthorYearShortTitle`.
- Detect collisions deterministically.
- Preserve a mapping from old keys to new keys.
- Search dependent documents before retiring any existing key.
- Avoid regenerating keys merely because row numbers change.

### 11\. Quality-control passes

Run separate checks for:

- Missing required fields by entry type
- Duplicate identifiers
- Duplicate normalized titles
- Invalid DOI, ISBN, PMID, and arXiv syntax
- Malformed URLs
- Suspicious dates
- Author-name variants
- Inconsistent venue names
- Unbalanced BibTeX braces
- Fields that will not survive XLSX-to-BibTeX conversion cleanly

Keep substantive accuracy issues separate from cosmetic normalization warnings.

### 12\. Human review and export

Use small approval batches—perhaps 25–50 records—organized by change type rather than changing everything at once.

After approval:

1. Apply changes to the canonical workbook.
2. Generate the BibTeX library programmatically.
3. Parse the generated BibTeX again to confirm validity.
4. Compare record counts and citation keys.
5. Produce a concise change report and old-to-new key map.
6. Spot-check the rendered citations in the target bibliography style.

Zotero could help retrieve and compare metadata, but it should serve as a reference and enrichment tool rather than automatically overwriting the library. Authoritative identifiers and publisher records should remain the basis for final decisions.
